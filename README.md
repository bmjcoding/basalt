# Basalt

The SRA Syndicate design system: one monochrome foundation for Blacksand, srasyndicate.io,
baileymjones.com, N1 and what comes next. Each product adds colour through one of Basalt's accent classes.

**Status:** Foundations, React components and a core SwiftUI component layer are built and
reviewed; no release has been published. See [what is complete and what remains](docs/status.md).
Agents working here follow [AGENTS.md](AGENTS.md). Motion primitives are in [docs/motion.md](docs/motion.md).

## Packages

| Package | What it is |
|---|---|
| [`packages/tokens`](packages/tokens) | Colour, type, space, radius, elevation and motion, as DTCG tokens built into CSS, TypeScript and JSON |
| [`packages/react`](packages/react) | React components on Base UI, styled with the tokens, with Phosphor icons |
| [`Sources/BasaltTokens`](Sources/BasaltTokens) | The tokens for SwiftUI (iOS 17, macOS 14, visionOS 1), generated from `packages/tokens`, with Geist bundled |
| [`Sources/BasaltUI`](Sources/BasaltUI) | Native buttons, inputs, toggles, surfaces, status, progress and empty states using the shared tokens |

## Use the tokens

```sh
npm install
npm run build
```

```css
@import "@srasyndicate/basalt-tokens/tokens.css";
/* optional: shadcn/ui variable names, mapped onto Basalt's */
@import "@srasyndicate/basalt-tokens/shadcn.css";

body {
  background: var(--basalt-surface-page);
  color: var(--basalt-text-primary);
  font: var(--basalt-font-weight-regular) var(--basalt-text-base-size) / var(--basalt-text-base-line-height) var(--basalt-font-family-sans);
}
```

The theme follows the operating system. To pin it, set `data-theme="dark"` or
`data-theme="light"` (or the `dark` / `light` class) on `<html>`.

## Use the tokens in SwiftUI

Basalt is not released, and its packages are private and `UNLICENSED`, with no `LICENSE` file: it is the owner's to use, not
yet open to anyone else. In the owner's own apps, add the package (`https://github.com/bmjcoding/basalt`, which needs access to
the repository), then:

```swift
import BasaltTokens

// once, at launch
Basalt.Fonts.register()

Text("Deploy")
  .basaltType(Basalt.TypeScale.base, weight: .medium)
  .foregroundStyle(Basalt.Colors.actionPrimaryText.color)
  .padding(.horizontal, Basalt.Space.s3)
  .frame(height: Basalt.Size.controlMd)
  .background(Basalt.Colors.actionPrimary.color, in: .rect(cornerRadius: Basalt.Radius.sm))
```

Colours follow the system's light or dark appearance. `Sources/BasaltTokens/Tokens.swift` is
generated by `npm run build`; never edit it by hand, and CI fails if it's stale.

For complete native controls, add the `BasaltUI` product and use
`BasaltButton("Deploy", variant: .primary) { … }` or apply `BasaltButtonStyle` to a native
Button. See [Apple usage and verification](docs/apple.md).

## Test

```sh
npm run check
swift test # on macOS
```

Builds the tokens and checks every text, boundary, focus and status pair against WCAG 2.2 AA
on every surface it can appear on, that every colour is inside sRGB, and that the page is
the darkest layer in both themes. Then builds the components and runs axe-core and keyboard
tests on them in a real browser, in both themes. CI also builds the Swift package and runs
its tests on macOS, including the same contrast checks on the generated Swift values.
`check` also validates every reference preview, typechecks the review pages, and installs
the packed npm archives in a separate temporary consumer. Run `npm ci` and install the
pinned Playwright Chromium before a first check; CI does both.

Opaque component labels render a second live instance for width, so hard-coded ids and controls can be duplicated in server HTML until hydration (permanently without scripts), and declining an unsafe component at hydration can change 600 to 400 and shift layout; a complete fix needs a larger server-safe reservation contract. The copied component is a second live instance on the client too, so its effects run twice.
